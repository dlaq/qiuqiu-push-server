# Find N5 / ColorOS 16 验收与 APP 使用说明

当前状态：**未连接真机，以下场景尚未执行。不能据此声称长期稳定、低功耗或流体云适配已通过。**

## APP 使用

1. 安装使用自己 Firebase 配置编译的 APK，在首页确认 Firebase 已配置，并授予通知权限。
2. 服务器页保存 HTTPS 地址，测试连接，然后使用后台生成的一次性配对码绑定设备。
3. 收到消息后在首页/通知页查看；点击详情可查看完整正文。Markdown 原生渲染；HTML 作为格式化文本展示，不执行脚本。
4. 需要主题和 API 管理时，在 APP 登录账户。订阅页创建业务 Topic 并将其绑定到本机，API 页可签发本机范围的凭证。
5. 业务设置页为服务器、安全、邮件、任务、网络、自定义选择默认声音，并进入 Android 的通知渠道设置调整系统声音、振动和重要性。发送方显式 sound 别名会使用对应的预建渠道变体，系统已设置的渠道不会被逐条覆盖。
6. HTTPS 默认允许；自定义 Deep Link 协议由用户在业务设置中显式允许。不可用链接回退到消息历史，不运行 javascript/data/file/content/intent URL。
7. 服务器状态为本地配置、权限和最近接收结果，不代表持续联网。无消息时应用不运行自己的周期网络任务。
8. 更换绑定设备时，先在后台撤销原设备授权；当前 APP 会阻止直接覆盖已有配对，需清除应用数据后重新绑定，避免遗留旧读取凭证。

## 可辅助采集的命令

在本人授权的测试设备上使用 adb：

```sh
adb shell dumpsys package io.qiuqiu.push
adb shell dumpsys notification --noredact
adb shell dumpsys jobscheduler
adb shell dumpsys activity services io.qiuqiu.push
adb shell dumpsys batterystats io.qiuqiu.push
```

`--noredact` 可能含消息内容，报告前须脱敏。Doze/重启/清除数据等操作会改变设备状态，执行前确保设备用于测试并记录恢复步骤。

流体云能力、FCM 的到达时延和 ColorOS 的后台策略，必须以真实设备结果为准；当前不依赖 Root、系统签名、Shizuku 或修改系统组件。
